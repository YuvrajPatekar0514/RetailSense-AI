# RetailSense AI — LLM & Generative AI Layer Specification

## 1. Executive Overview

The **LLM & Generative AI Layer** in **RetailSense AI** handles natural language understanding (NLU), goal interpretation, task planning assistance, agent routing, business executive summaries, customer service responses, and structured decision explanations.

> [!CAUTION]
> **STRICT ZERO NUMERICAL FABRICATION GUARANTEE**
> 
> The LLM is **STRICTLY PROHIBITED** from fabricating or hallucinating numerical business metrics (prices, sales volume, stock levels, forecast units, costs, discounts).
> 
> All numerical figures are populated exclusively by:
> 1. **Factual Data**: Verified database tables (`database.repositories`) & tools.
> 2. **Model Predictions**: Trained Machine Learning models (`Random Forest`, `XGBoost`).
> 3. **Retrieved Knowledge**: RAG vector store chunks & store policies.

---

## 2. Explicit Data Separation in Decision Explanations

Every operational decision generated by the system is bound to the `DecisionExplanation` Pydantic schema, enforcing clean separation across four distinct pillars:

```
+-----------------------------------------------------------------------------------+
|                            DecisionExplanation (Pydantic)                        |
+-----------------------------------------------------------------------------------+
| 1. FACTUAL DATA        │ Source DB/Tool metrics (current stock, reorder point)    |
| 2. MODEL PREDICTIONS   │ ML demand predictions (horizon, forecast units, MAE)    |
| 3. RETRIEVED KNOWLEDGE │ RAG document chunks (approval policy, warranty rules)   |
| 4. GENERATED NARRATIVE │ Synthesized natural language explanation (LLM narrative) |
+-----------------------------------------------------------------------------------+
```

---

## 3. Structured Pydantic Schemas (`llm/schemas.py`)

### 3.1 `DecisionExplanation` Schema
```python
class DecisionExplanation(BaseModel):
    decision: str                            # High-level decision summary
    reasoning_summary: str                   # Step-by-step reasoning narrative
    supporting_data: FactualData             # DB/tool factual metrics
    model_predictions: Optional[ModelPrediction] # ML forecast metrics
    retrieved_knowledge: List[RetrievedKnowledge] # RAG knowledge chunks
    sources: List[str]                       # Authoritative sources used
    confidence: float                        # Confidence score (0.0 to 1.0)
    recommended_action: str                  # Action plan for user
    generated_explanation: str              # Natural language narrative explanation
```

## 4. Execution Auditability & Metadata Logging (`LLMAuditMetadata`)

Every LLM call logs audit metadata to system logs and persistent database tables (`agent_runs` / `tool_calls`):

- **`call_id`**: Unique invocation ID (`LLM_CALL_17593...`)
- **`model_name`**: LLM identifier (`gpt-4o-mini`)
- **`task_name`**: NLU or explanation task (`interpret_goal`, `generate_decision_explanation`)
- **`prompt_template`**: Template identifier used
- **`latency_ms`**: Latency in milliseconds
- **`tokens_used`**: Token usage breakdown (`prompt_tokens`, `completion_tokens`, `total_tokens`)
